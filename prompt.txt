Desarrolla la página `Catalogo` (y sus archivos asociados) para el proyecto What2Cook. Stack: HTML, CSS vanilla, JS vanilla, PHP sin framework. La página consume la API de Spoonacular, tal como lo hacen los asistentes de cocina y de dietas.

**Contexto del proyecto:**
- Antes de escribir código nuevo, revisá los archivos existentes e identificá componentes reutilizables: llamadas a Spoonacular, funciones JS de renderizado de recetas, estilos CSS de cards, sistema de autenticación PHP, estructura de header/footer.
- Respetá las convenciones de naming, estructura de carpetas y patrones de código ya establecidos en el proyecto.

**Funcionalidad requerida:**

1. **Listado de recetas** — Grid de cards precargadas al entrar a la página. Cada card muestra: imagen, nombre, tiempo de preparación, badges de restricciones dietarias. Al hacer click abre vista de detalle.

2. **Vista de detalle individual** — Modal o página separada (usá el patrón que ya exista en el proyecto) con: imagen destacada, lista de ingredientes con cantidades, instrucciones paso a paso numeradas, tabla de información nutricional (calorías, proteínas, carbohidratos, grasas).

3. **Filtros** — Panel de filtros con tres ejes independientes acumulables:
   - Categoría (breakfast, lunch, dinner, dessert, snack, soup, salad, etc.)
   - Tipo de cocina (Italian, Mexican, Asian, American, Mediterranean, etc.)
   - Restricción dietaria (keto, vegan, vegetarian, gluten-free, paleo, primal, whole30, lacto-vegetarian, ovo-vegetarian, pescatarian)
   - Los filtros se aplican vía parámetros de la API Spoonacular (`diet`, `cuisine`, `type`), no filtrado client-side sobre datos ya cargados.

4. **Paginación o carga incremental** — Implementá el patrón que ya use el resto del proyecto. Si no existe ninguno, usá paginación simple con botones Anterior/Siguiente. Spoonacular soporta `offset` y `number` en `/recipes/complexSearch`.

5. **Favoritos** — El botón de favorito en cada card y en la vista de detalle es visible para todos, pero funcional solo para usuarios autenticados. Si el usuario no está logueado, redirigir a login al intentar guardar. Si está logueado, persistir el favorito usando el mismo mecanismo que ya use el proyecto (sesión PHP + base de datos, o lo que corresponda). El estado del ícono debe reflejar si la receta ya está guardada.

**Endpoint principal de Spoonacular a usar:**
- `GET /recipes/complexSearch` con parámetros: `query`, `cuisine`, `diet`, `type`, `number`, `offset`, `addRecipeInformation=true`, `addRecipeNutrition=true`
- `GET /recipes/{id}/information` para el detalle individual si fuera necesario.

**Instrucciones de implementación:**
- Revisá el código existente antes de crear cualquier archivo nuevo.
- Reutilizá funciones, estilos y componentes donde sea posible.
- Respetá el sistema de autenticación ya implementado sin modificarlo.
- Los archivos PHP que hagan llamadas a Spoonacular deben leer la API key desde variable de entorno o archivo de configuración ya existente en el proyecto, no hardcodearla.
- El diseño visual debe seguir los wireframes adjuntos y ser consistente con las páginas ya desarrolladas.
- No introduzcas dependencias externas (librerías, frameworks) que no estén ya en el proyecto.
